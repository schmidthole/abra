# observable dispatch capabilities

- [preflight] before reserving an expensive attempt, inspect actual available harness/profile
configuration and its tool allowlist. record profile/configuration source, observed
allowed tools, authorized path writes, independence mode and limitations in the
filled brief's capability_evidence. there is no portable introspection api,
capabilities cli, probing service or runtime. use documented native facilities only.
previous success is evidence, not a guarantee for a new session/profile.

| role | required observed facilities | forbidden expansion |
| --- | --- | --- |
| worker | worktree reads/writes; shell/git/python/helper; required tests/formatter; task commit and assigned tracker/report writes | no publication, coordinator records or extra agents |
| verify | fresh independent context; detached exact-head git/read/shell/test/formatter; authorized disposable probes/build outputs; python/helper and assigned tracker/report writes | no product repair, worker-tree edits, commit or publication |
| scout/plan | source/reference reads; python/helper execution; assigned tracker/report writes; fresh context for independent research/validation | null directory grants no other project commands; no source edits/probes |
| triage | source/evidence reads; python/helper and assigned tracker/report writes; only explicitly authorized local diagnostic probes in supplied worktree | no production/shared mutation, fixes or expanded access |

preparation may inspect path accessibility, supplied helper --help, interpreter/tool
versions and pinned formatter validation. the coordinator never initializes an
agent-owned tracker as a capability probe. help success does not prove future write
permission, fresh context or complete tests. observe the actual launched agent's
helper round trip, exact-head/check availability and report write; save evidence in
existing brief/report references, not a capability registry. unsupported profiles
block before substantial work. if inspection cannot establish required capability,
use a separately authorized minimal disposable native trial or report blocked.

- [capability-failure] post-launch tool/helper/test/report failure blocks required work: preserve last
state and report redacted failure, reconcile native ownership and actual evidence
before replacement. absent tracker is not proof no agent ran. do not suppress
tracking/tests, self-approve, or launch again to compensate for missing tools. no
compliant independent verifier means blocked delivery. no preflight grants network,
production or publication authority. vendor-specific selection notes stay in
`CLAUDE.md` (or that harness's instructions), not portable role contracts.

## evidence and limits

the current core worker and policy worker are actual execution-capable native
assignments: shell/git/python/helper, candidate worktree edits and canonical checks
are observed in their task reports/checkpoints. final fresh detached verification
must record its own observations. these facts do not certify other profiles or
harnesses. supported codex/claude native facilities remain configuration-dependent;
no external harness or restricted-profile native trial is claimed here.

for a separately authorized disposable harness trial, record profile/allowlist,
agent-owned helper init/read/update, exact-head inspection, canonical tools, report
write and independence evidence; deliberately restricted profile must stop blocked
without duplicate dispatch. static contract tests cannot establish live availability.
